## Description

CampoSync is a phytosanitary compliance engine for ~900,000 Spanish agricultural farms. This `BigData` branch adds a Big Data layer on top of the existing Spring Boot application, implementing two experiments:

- **Exp1 — Retrieval Accuracy:** comparison of 4 search methods over the official RETO catalogue (Spanish Ministry of Agriculture): Exact Match, TF-IDF, BM25 and pgvector Embeddings.
- **Exp2 — Query Performance (N+1):** Hibernate JPA N+1 benchmark with 100,000 real records, comparing 4 loading strategies: LAZY, EAGER, JOIN FETCH, EntityGraph.

## Step-by-step reproducibility

### Step 1 — Clone and switch to BigData branch

```bash
git clone <repo-url>
cd camposync
git checkout BigData
```

### Step 2 — Environment variables

Copy `.env.example` to `.env` in the `camposync/` root and fill in:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=agro_data
DB_USER=admin_saas
DB_PASSWORD=<your_password>
```

### Step 3 — Start the database

```bash
docker compose up -d postgres
```

Verify the container is healthy:
```bash
docker ps --filter name=camposync-postgres
```

### Step 4 — Apply Flyway migrations (includes pgvector)

```bash
# Start Spring Boot once so Flyway applies V1–V14
./mvnw spring-boot:run &
# Wait for "Started CamposyncApplication" (~30s) then stop with Ctrl+C
```

Migration `V14__pgvector_embeddings.sql` activates the `vector` extension, adds the `embedding vector(384)` column and creates the ivfflat cosine index on `producto_fitosanitario`.

> **Alternative without starting the app:**
> ```bash
> docker exec -i camposync-postgres psql -U admin_saas -d agro_data \
>   < src/main/resources/db/migration/V14__pgvector_embeddings.sql
> ```

### Step 5 — Python environment

```bash
cd big-data
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt --only-binary=:all:
```

### Step 6 — Download RETO catalogue

```bash
python reto_scraper.py
# Output: data/reto_productos.csv  (2,045 products)
```

### Step 7 — Ingest embeddings into pgvector

```bash
python ingest_reto.py
# Generates vector(384) per product and UPSERTs into producto_fitosanitario
# Estimated duration: ~15 seconds on CPU
```

Verify:
```bash
python ingest_reto.py --test
# Should show: pgvector: ACTIVE, with embedding: 2045
```

## Experiment 1 — Retrieval Accuracy

### Generate annotated dataset

```bash
cd exp1-retrieval
python generate_dataset.py
# Output: data/queries_annotated.csv  (841 queries)
```

### Run full evaluation

```bash
python evaluate.py
# Runs all 4 methods → results/metrics_comparison.csv + results/metrics_chart.png
```

Without DB connection (baselines only):
```bash
python evaluate.py --skip-embeddings
```

| Method | Precision@1 | Recall@5 | F1-Score |

See `exp1-retrieval/results/metrics_chart.png` for the comparison chart.

## Experiment 2 — Query Performance (N+1)

### Seed 100,000 treatments

With Spring Boot **stopped** and DB running:

```bash
cd exp2-query-performance/data
python seed_100k.py
```

Verify:
```bash
docker exec camposync-postgres psql -U admin_saas -d agro_data \
  -c "SELECT COUNT(*) FROM tratamiento;"
# Expected: 100000
```

### Run the benchmark

Start Spring Boot:
```bash
./mvnw spring-boot:run
```

In another terminal:
```bash
cd big-data/exp2-query-performance
chmod +x run_all.sh
./run_all.sh
# Output: results/latency_comparison.csv + results/latency_comparison.png
```

### Results (3,747 treatments per request)

| Strategy | Concurrency | Throughput | Avg Latency | P95 |
|----------|-------------|------------|-------------|-----|
| LAZY (N+1) | 100 | 5.83 req/s | 13.350 ms | 17.407 ms |
| EAGER (N+1) | 100 | 5.72 req/s | 13.302 ms | 17.760 ms |
| **JOIN FETCH** | **100** | **21.24 req/s** | **3.617 ms** | **4.885 ms** |
| EntityGraph | 100 | 20.13 req/s | 3.808 ms | 5.089 ms |

**JOIN FETCH eliminates the N+1 problem**: 3.6× higher throughput, 72% lower P95 latency vs LAZY/EAGER.

## Phase 6 — Production integration (smart search)

Exp1 findings transferred to the real application:

- **Endpoint:** `GET /api/productos/search?query=...` → lexical search with LIKE on name, active ingredient and authorized crops. 50 results max, response time <3 ms.
- **Accent normalization:** Java `Normalizer.NFD` strips diacritics before querying (`"Cúprico"` → finds `"CUPRICO"`).
- **Query Expansion:** colloquial terms mapped to real active ingredients (`"fungi"` → `"cobre"`, `"slugs"` → `"metaldehido"`).
- **Frontend:** `ModalNuevoInventario.jsx` uses 250ms debouncing and lazy loading (modal opens instantly).
